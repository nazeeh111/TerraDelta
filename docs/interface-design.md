# Analyst workspace

The embedded interface follows the analyst's evidence path: choose a complete imported area and an observation interval, query event history, inspect an event's timing support and its actual source images, then export a recorded answer. It makes no global coverage or causal attribution claim. Native monthly imagery occupies the center; a separate source-month selector does not change the event query dates.

The interface uses local system typography, warm neutral surfaces and restrained green accents. Proposed, reviewed and retracted states carry text labels as well as distinguishable outline styles and colors. Transparent source pixels expose a checkerboard exclusion pattern. Selected event outlines gain a white halo so their native geometry remains visible over varying imagery.

`index.html`, `style.css` and `app.js` are dependency-free package assets. The service should mount these files at `/web` and serve `index.html` at `/`. It must provide the agreed `/api/catalog`, `/api/events`, `/api/events/{id}/history`, `/api/regions/{id}/frames/{index}.png` and export endpoints. Canvas geometry projection is explicitly limited to EPSG:3857 source grids with WGS84 event geometries, matching the validated SpaceNet 7 adapter. Other source CRSs show imagery without silently drawing incorrectly positioned overlays.

The main map retains the complete area without initial event cropping. Its displayed width is capped from available desktop viewport height and the actual native aspect ratio. The image and canvas share the same bounds; no letterboxed object-fit region is projected as imagery. Smaller layouts retain full-width, full-area viewing.

Selecting an event replaces the card list with its inspector in the same right-panel position. Back to events restores the existing query page and keyboard focus. Timing and supporting imagery lead; source availability, footprint area and model score follow. Every cited URI, source ID/hash, processing revision and ledger timestamp remains clearly available in collapsed Sources and provenance. A score is labeled as a model score, not legal or physical truth.

The event list renders at most 100 cards per page. Previous and Next controls have explicit accessible labels and a live range such as “1–100 of 9,550 events.” A page change resets the list scroll position and focuses the range. Paging only changes the list: all returned features remain on the complete-area map and in the snapshot-bound exports. It does not request another answer or change the snapshot. Entering the inspector hides the page controls; Back restores the prior page. New area/date/state queries reset the page to the beginning, and pending, failed and empty results hide the controls.

Supporting-image roles come from `quality.support_before_index`, `support_first_index` and `support_current_index`. Every selected frame must match a cited source by both source ID and SHA-256. Indices are deduplicated and roles combined when one observation has more than one role. The current role distinguishes confirmation, retraction and a still-proposed hypothesis. If no role indices can be resolved, exact cited frames may appear only under the generic Cited observation label; no before/after role is invented.

Inspector thumbnails request `/api/regions/{region}/frames/{index}.png?detail_event={id}&detail_revision={revision}` for the exact returned event revision. They are labeled Native-pixel detail and use no enhancement. Missing exact details show an unavailable message rather than substitute different bytes. Selecting a thumbnail uses the plain frame URL to open the complete area. The source panel retains acquisition support, publication uncertainty, source coverage and registration diagnostics.

Query results preserve their returned snapshot token in export links. A snapshot may be copied and replayed. The inspector explicitly marks its returned revision. Revision history can include newer records, but it cannot replace that selected answer automatically. Each history row distinguishes source availability (`detected_at`) from ledger recording time (`record_time`); reconstruction clocks are not physical event dates. Empty results explicitly differ from observed no change; unavailable/quality-rejected imagery receives its own status. Starting a new query clears the previous overlays and disables prior export links. Fetch failures show a persistent error rather than presenting stale results under new dates or displaying a fabricated empty success.

The default event state is **Model confirmed**. Proposed, reviewed, retracted and all-state queries remain available. A state change issues a new area/date/state history query; it does not download all proposal records and then merely hide them. `/api/events` and both export links carry the identical optional `state` parameter. All-state requests omit that parameter for API compatibility. Export links also retain the exact returned snapshot token.

An explicit Retracted choice includes retracted records even if they were excluded in an earlier all-state query. The retraction checkbox becomes checked and disabled while that explicit choice applies; leaving it restores the user's prior checkbox preference. All states with the checkbox unchecked excludes retracted events. Checkbox changes also refresh the query, so the displayed records and export selection agree.

New queries abort superseded fetches and invalidate prior history-detail responses. The sequence guard still rejects late results if cancellation is ignored. Validation failures also invalidate older pending requests and leave no stale snapshot, overlay or export under the new controls. The complete-area imagery is independent of the event-state query. Queries still return the complete matching answer; bounded card rendering does not reduce network payload or guarantee response times for large all-state queries.

A persistent Study validation banner reads `catalog.study_status` as plain text, with an explicit unknown/experimental fallback. Validation failure is not confined to a collapsed limits panel or a research badge, and these interface improvements do not change the failed study result.

Accessibility includes native labeled form controls, keyboard-accessible result buttons, a skip link, visible focus rings, text alternatives for source previews, live query/error feedback and a native modal dialog. Event cards provide the keyboard equivalent of canvas selection. Layouts adapt from three desktop columns to stacked mobile content; transitions respect reduced-motion preferences.
